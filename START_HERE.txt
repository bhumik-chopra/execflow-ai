ExecFlow AI - Windows startup guide
===================================
Project: C:\codes\assignment 1 bhumik\execflow-ai

The existing frontend/backend and MongoDB Atlas data are preserved.
No paid AI API key is required. Language processing runs locally with Ollama.
No Docker or local MongoDB server is required.

ONE-TIME SETUP
--------------
1. Install Python 3.11+, Node.js, and Ollama:
   https://www.python.org/downloads/
   https://nodejs.org/en/download
   https://ollama.com/download/windows

2. Open a new terminal after installing Ollama. Download the model:

   ollama pull llama3.2:3b

   If the command is not found in an older terminal, use:

   & "$env:LOCALAPPDATA\Programs\Ollama\ollama.exe" pull llama3.2:3b

3. Start Ollama if its Windows app is not already running:

   ollama serve

   Leave this terminal open. If pull cannot reach the daemon, run serve first
   in a separate terminal, then retry pull. An existing daemon does not need
   a second serve process.

4. Configure MongoDB Atlas: create a database user with read/write access to
   execflow, add your current IP to Network Access, and obtain your cluster's
   Python driver URI from Connect. Use database credentials, not your web login.

5. Configure backend/.env (do not overwrite existing credentials):

   MONGODB_URI=your_mongodb_atlas_connection_string
   MONGODB_DB=execflow
   OLLAMA_BASE_URL=http://localhost:11434
   OLLAMA_MODEL=llama3.2:3b

   Root .env is also supported. Existing root MongoDB credentials can stay there.
   Settings in backend/.env override root .env; OS environment overrides both.
   Both files are gitignored. Do not put credentials in frontend.

   For a fresh setup only, from the project root:
   Copy-Item .env.example backend/.env
   notepad backend/.env

INSTALL / UPDATE BACKEND DEPENDENCIES
-------------------------------------
   cd "C:\codes\assignment 1 bhumik\execflow-ai\backend"
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt

Skip virtual-environment creation if it already exists.

START BACKEND - SEPARATE TERMINAL
---------------------------------
   cd "C:\codes\assignment 1 bhumik\execflow-ai\backend"
   .\.venv\Scripts\python.exe -m uvicorn main:app --reload

With an activated environment, use uvicorn main:app --reload instead.
Restart the backend after changing .env.

START FRONTEND - ANOTHER TERMINAL
----------------------------------
   cd "C:\codes\assignment 1 bhumik\execflow-ai\frontend"
   npm.cmd install
   npm.cmd run dev

You only need npm.cmd install on first setup or after dependency changes.

OPEN
----
App:      http://localhost:5173
API docs: http://localhost:8000/docs
Health:   http://localhost:8000/health

CHECK / RETRY
-------------
   Invoke-RestMethod http://localhost:8000/health

backend and mongodb should be ok. ollama is ok only when the server is reachable
and the configured model is installed. Health never performs generation.

If local AI is unavailable, raw input is still saved with PENDING status and
HTTP 503 reports its source_id. Start Ollama, then retry that saved source:

   Invoke-RestMethod -Method Post 'http://localhost:8000/api/sources/SOURCE_ID/process?as_of=2026-09-25T09:00:00'

Already processed sources are cached and do not call AI again. Briefs, tasks,
calendar conflicts, and audit retrieval use Python/MongoDB and remain available.

To verify local generation after downloading the model:

   ollama run llama3.2:3b "Reply with exactly OK."

Existing raw assignment seed (from backend):
   .\.venv\Scripts\python.exe -m seed.seed

A fully processed seed's second run makes zero AI calls. Pending/failed seed
sources still require processing. Do not expect a seed to work before the model
is installed. The provider patch does not reset or replace existing Atlas data.

TESTS (NO REAL MODEL OR ATLAS NEEDED)
-------------------------------------
   cd "C:\codes\assignment 1 bhumik\execflow-ai\backend"
   .\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
   .\.venv\Scripts\python.exe -m pytest ../tests -q

PORT CONFLICTS
--------------
   Get-NetTCPConnection -LocalPort 8000 -State Listen -ErrorAction SilentlyContinue

Stop an old server in its own terminal with Ctrl+C. If another app needs port
8000, use --port 8001 for the backend and set frontend/vite.config.ts proxy target
to http://127.0.0.1:8001, then restart both servers. Do not blindly kill another
application. Stop the frontend with Ctrl+C when finished.

Data handling: language processing runs on the configured local Ollama server;
raw sources and structured state remain in MongoDB Atlas. Atlas needs internet.
